# Vuo code quality and security audit

**Date:** 2026-09-02
**Commit audited:** `33d3bd9` (`main`, merge of PR #9)
**Scope:** the whole repository: `vuo-core`, `vuo-shim`, `harbour-vuo`, `qml/`, build scripts, CI workflows, packaging, systemd units, dependency lockfiles.

---

## 1. Summary

Vuo's security posture is unusually strong for a pre-1.0 client. The rules in `docs/scope.md` §9 are actually implemented, not just written down: TLS cannot be disabled, redirects are followed by hand with origin pinning so the API token never leaves the configured server, every SQL statement is parameterised, the HTML transform is an allowlist over a closed block enum, every QML label that renders foreign text uses `Text.PlainText`, image loading is consent-gated per origin, icons are sniffed and size-capped before Qt's decoder sees them, and panicking calls are denied by lint in every crate. No vulnerability was found that would let a feed or a malicious server execute code, exfiltrate the token, or crash the process.

What the audit did find is concentrated in three places:

1. **Sync robustness.** Three defects let an ordinary misbehaving server or proxy stall sync permanently, force a full-corpus re-pull on every pass, or silently stop new entries from ever arriving. These are the most important findings.
2. **The HTML transform's edge cases.** A six-byte self-closing tag erases the rest of an article, and a 2 MB input can inflate to about 48 MB of spans without tripping any cap. Neither is a code-execution risk, but both are exactly the "feed operator versus phone" failures §9.2 exists to prevent.
3. **UI plumbing.** The Feeds page permanently re-scopes a shared list model, subscribe results never reach the user, and several image-sizing paths are unbounded.

Dependency scanning is clean: `cargo audit` reports zero advisories across both lockfiles, and the TLS stack is current rustls with no OpenSSL anywhere in the graph.

## 2. High

### H1. One wrong-typed field in one entry stalls sync permanently on that window **[probe]**

`crates/vuo-core/src/api/wire.rs:75-81` and `:92-128`. `EntriesResponse.entries` is `Vec<Entry>` with strictly typed fields (`id: i64`, `starred: bool`, `reading_time: i32`, `tags: Vec<String>`). `#[serde(default)]` only covers *absent* fields. A wrong *type* fails deserialisation of the whole response in `client.rs:239`, which becomes `Error::Protocol`, which `pull.rs:194` propagates with `?`. The cursor never advances past that page, so every later pass re-fetches from the same cursor and dies on the same row.

Confirmed inputs that kill a page: `"reading_time": 4294967296` (Miniflux's Go `int` is 64-bit), `"starred": "yes"`, `"id": 2.5`, `"tags": [1,2]`, `"total": "2"`.

This contradicts the module's own doc ("make serde succeed on any plausible server response") and §9.2 ("reject the entry rather than the sync"). No test covers a wrong-typed field.

**Fix.** Deserialise `entries` as `Vec<serde_json::Value>` (or a lenient vector that maps per-element failure to `Error::Item`) and convert each element individually in `convert::entries`. Widen `reading_time` and `parsing_error_count` to `i64` and clamp in `convert`. Add a test: one poisoned row in a page of 250 rejects one row, not the page.

### H2. A failing `/v1/entries/ids` aborts the sync after the pull, and the cursor is never persisted **[probe]**

`crates/vuo-core/src/sync/mod.rs:103-104` calls `pull::reconcile(db, client).await?`; the cursor is persisted only at `:126-138`, after it. Reconcile runs whenever it is "due", which is true forever on a fresh mirror and whenever a reconcile never completes, on any server reporting 2.3.2 or later.

Reproduced against a 2.3.2 server whose `/v1/entries/ids` returns 404: three passes, every pass `Err`, `cursor = None`, and every `/v1/entries` request has no `changed_after`. That is a full-corpus pull of up to 400 pages of 250 rows, every pass, forever. Real triggers: a reverse proxy that does not forward that path, a version string that over-reports, a persistent 5xx on that one endpoint. The counters call one line above is already best-effort (`unwrap_or_default()`); reconcile is not, even though its own doc (`pull.rs:318-319`) says a reconcile that does not run merely leaves the cache "slightly stale".

**Fix.** Treat a reconcile *error* like an abort (return `Reconcile::aborted()` and warn), or persist the cursor before step 4. Add an orchestration test.

### H3. A far-future `Date` header poisons the cursor and new entries never arrive again **[probe]**

`crates/vuo-core/src/api/transport.rs:328-333` parses `Date` with no sanity bound; `pull.rs:200-202` and `:254-255` persist `date - 60` as the cursor. With `Date: Fri, 02 Jan 2099` the persisted cursor is `4071006185` and sync reports success. Every subsequent pull sends `changed_after` in 2099 and receives nothing. Even if the upstream clock is later corrected, the entries changed in between are permanently skipped, because the healing pass persists a cursor ahead of them.

This does not need a hostile server. nginx replaces the upstream `Date` with its own clock by default, so any proxy or CDN host with a wrong clock triggers it.

**Fix.** `cursor = min(server_now, local_now) - CURSOR_SKEW_SECS`. Clamping toward the local clock can only re-pull more, never less. Warn when the two clocks differ by more than a day. Add a test.

### H4. Opening a feed permanently re-scopes the current tab's entry model

`qml/components/EntryListView.qml:165-168` passes the *current tab's* model (`entries`, `starredEntries` or `allEntries` from `harbour-vuo.qml:47-49`) to FeedListPage as `entryModel`. `qml/pages/FeedListPage.qml:100-107` pushes EntryListPage with that model and `scopeKind: 3`; `qml/pages/EntryListPage.qml:110-114` then calls `setScope(3, feedId)` on the shared object. Nothing ever restores scope 0/1/2: `applyScope()` is a no-op for the root page and `EntryListView.qml:47-49` scopes only in `Component.onCompleted`. `models.rs:494-497` confirms `setScope` is a plain overwrite plus reload, and the 1.5 s poll keeps reloading under the feed scope.

**Trigger.** Unread tab, pulley "Feeds", tap any feed, back, back. The Unread tab now lists that feed's entries, including read ones, until restart. The comment at `EntryListPage.qml:35-53` describes this exact bug as fixed; the move to per-tab models reintroduced it.

**Fix.** Add a fourth `EntryModel { id: browseEntries }` in `harbour-vuo.qml` and pass that from the Feeds menu item, or have EntryListPage create its own model when `!showScopeTabs`.

## 3. Medium

### Content transform (`crates/vuo-core/src/content/transform.rs`)

**M1. Self-closing syntax on a non-void block element silently erases the rest of the article. [probe]**
`start_tag` line 599 sets `childless = is_void(&name) || tag.self_closing`, then lines 693-704 call `start_block` (which mutates `pre_depth`, `table`, `lists`, `quote_depth`) without pushing the element on `open`, so `close_element` never undoes it. `<p>before</p><pre/><p>after</p>` yields `["before"]` with `truncated: None`; every later character goes into `pre_text`, which `finish()` never emits. `<table/>` does the same via "stray text inside a table"; `<blockquote/>` permanently raises quote depth; `<ul/>` makes every later paragraph a bullet. XHTML-serialised feeds legitimately emit `<pre/>` for an empty `pre`. HTML ignores the self-closing flag on non-void elements; this code honours it.
*Fix:* only honour `tag.self_closing` for `Disposition::Skip` (foreign content). Add `<pre/>` and `<table/>` regression tests.

**M2. Span count is not bounded by any cap; 2 MB in, about 48 MB out. [probe]**
`max_text_bytes` bounds text bytes, not `Span` structs (120 bytes each, plus a heap `String`). Every `<br>` pushes an uncharged `"\n"` span (lines 826-832) that never coalesces, and every style change starts a new span. `<p>` plus `"x<br>"` repeated 400 000 times is 2 000 007 bytes, inside the input cap, and produces one paragraph with 400 000 spans and `truncated: None`. `<b>a</b>a` with a 1000-byte text cap produced exactly 1000 spans. The fuzz target asserts on none of this.
*Fix:* charge a fixed per-span overhead to `text_bytes` on every new span and charge the `\n`; or add `max_spans_per_block`. Add a fuzz assertion bounding total span count.

**M3. Depth cap is reached by ordinary unclosed `<p>`, `<li>`, `<tr>`, `<td>`, after which structure stops. [probe]**
Lines 658-661 return before `start_block` once `open.len() >= max_depth`. The tokenizer does not close `<p>` when the next `<p>` opens (that is the tree builder's job, and there is none), so `"<p>para "` repeated 300 times gives 128 blocks and then 172 paragraphs merged into the last block. A 300-row table with unclosed `<tr>`/`<td>` keeps 42 rows; the rest flows into the last cell.
*Fix:* implement the handful of implied end tags the spec defines for `p`, `li`, `tr`, `td`/`th`, `dt`/`dd`. At minimum, still flush for those elements past the cap.

**M4. Loose ordered lists lose their numbers; text after a nested list is mis-attributed. [probe]**
`flush` (lines 447, 482) resets `pending` to `default_pending()` even when spans are empty, so `<ol><li><p>one</p></li>...` (what every Markdown renderer and WordPress emit) yields `number: None` for every item. `close_element(List)` flushes before `lists.pop()`, so text after a nested list comes out at the inner list's indent.
*Fix:* do not reset a numbered `ListItem` on an empty flush; in the `List` close arm, recompute `pending` after the pop. The same ordering issue affects `<h2><div>x</div></h2>`.

**M5. StyledText escaping may render `&#39;` and `&amp;` literally on the device.** *(needs on-device confirmation)*
`block.rs:104-107` and `:153-164` escape `'` as `&#39;` and `&` inside `href` as `&amp;`. Qt's `QQuickStyledText` (Qt 5.6 on Sailfish) is not an HTML parser; its documented entity set is `&gt; &lt; &amp;` (plus `&quot;` and `&nbsp;` in the code), it does not decode numeric references, and it appears not to decode entities inside attribute values at all. If so, every apostrophe in article text renders as `&#39;`, and every link with a two-parameter query has a broken `href`. `MediaUrl`'s serialisation provably contains no `"`, `<` or `>` (the `url` crate percent-encodes them), so the href can be emitted verbatim.
*Fix:* verify on a device; drop the `'` arm; emit `href` verbatim guarded by a unit test that `MediaUrl::as_str()` never contains those three characters.

### Database and sync (`crates/vuo-core/src/{db,sync}`)

**M6. 411/413/414/415/431 discard queued user actions although none mean "this payload is invalid". [probe]**
`error.rs:181-185` lists them in `is_permanently_rejected`; `replay.rs:67-86` then discards the batch. 413 is a proxy's request-size verdict (nginx `client_max_body_size`); the right response is to split the batch, not delete 500 marks. 431 concerns request headers. A PUT answered 413 with three queued marks produced `dropped = 3` and an empty outbox. This is exactly the failure the comment above that list says it exists to prevent.
*Fix:* keep only 400 and 422; on 413 halve the batch size and retry.

**M7. Feed removal eagerly deletes outbox rows on the strength of one feed listing, with a false justification.**
`store.rs:190-199` and `:291-297` delete outbox rows because "`confirm` matches nothing, so the row would sit forever". But `outbox::confirm` (`outbox.rs:299-312`) deletes by `(entry_id, field, value)` after a 204, and Miniflux ignores unknown ids and returns 204, so such rows *do* clear on the next flush. The eager delete is unnecessary, and it turns any partial or stale `/v1/feeds` body other than the exact-`[]` case into loss of pending marks and stars for every feed absent from it. `tests/sync_pull.rs:664-704` pins the behaviour with the same wrong rationale.
*Fix:* drop the outbox deletes from `delete_feed` and `delete_entry`; fix both comments and the test.

**M8. Icons are stored under the response's id rather than the feed's `icon_id`, so a mismatch re-fetches forever. [probe]**
`sync/mod.rs:166` discards `_icon_id`; `api/icon.rs:117` uses `w.id`; `store.rs:579-584` matches `icons.id = f.icon_id`. A feed with `icon_id: 77` whose icon body says `"id": 0` is fetched every pass, resets `icon_failures` on each success, and occupies one of the eight per-pass slots permanently. That is the starvation migration 2 was written to prevent.
*Fix:* store under the feed row's `icon_id`, or treat a mismatch as a failure.

**M9. Categories are never deleted. [probe]**
`pull.rs:82-142` reconciles feeds but not categories; there is no `DELETE FROM categories` in the workspace. `store.rs:110-116` also inserts empty-titled placeholder categories that are never cleaned. A category deleted in the web UI stays on the phone indefinitely.
*Fix:* mirror the feed logic with the same non-empty-listing guard; the FK already has `ON DELETE SET NULL`.

**M10. Reconcile accumulates up to 5 000 pages and 5 million ids before checking anything.**
`pull.rs:334-352` stops only on a short page or `offset > 5_000_000`. `declared_total` is read at `:337-339` but not used as a bound until `:366-377`. A server that keeps answering full pages costs 5 000 sequential requests and roughly 50-90 MB of `HashSet<i64>` on a phone.
*Fix:* abort as soon as `seen.len() > total` or `offset >= total`.

**M11. UI sync and the systemd timer's sync have no mutual exclusion.**
`vuo-shim/src/worker.rs:334`, `:384` and `:1008-1014` (`--sync-once`) all call `sync::sync` on separate connections; nothing takes a lock. Sequence: the timer starts an id listing at T; entry X is created server-side at T+1 s; the UI pulls X at T+90 s; the timer finishes its listing at T+120 s and `pull.rs:379-397` deletes X as stale; the UI persists a cursor past X. X is gone until a future reconcile, which can only delete. Needs a large corpus and an overlap, both realistic with a 30-minute timer plus user refreshes.
*Fix:* an advisory `flock` on a sidecar file around `sync()`, or have reconcile skip rows inserted after the listing started.

### Qt shim (`crates/vuo-shim/src`)

**M12. Subscribe results never reach the user; unsubscribe results go to a slot nobody drains.**
`worker.rs:378-400`: the `Subscribe` arm only calls `on_event(...)` (the log sink) and never posts a `Notice`. The `Unsubscribe` arm posts `Notice::SubscriptionChanged`, but no model consumes that variant; `models.rs:422`, `:864` and `settings.rs:355` all re-post it as "not mine". Entering a non-feed URL closes the dialog and shows nothing, ever.
*Fix:* post the notice from `Subscribe`; add a drain in `FeedModel` with `subscribeError`/`subscribeSerial` and poll it from the page.

**M13. Take-then-repost on the single notice slot can overwrite a fresh worker notice.**
`models.rs:416-422`, `:854-864`, `settings.rs:348-358` do `take_notice()` then `post(other)` as two mutex acquisitions, while the worker's `post` (`context.rs:606-610`) is a blind overwrite. An orphaned `SubscriptionChanged` (M12) is re-taken and re-posted by three models every 1.5 s for the life of the process, so the window recurs indefinitely. An unsubscribe followed by "Test connection" can lose the `ConnectionTested` notice, and the Settings page's 400 ms poll then runs forever.
*Fix:* a `Mutex<VecDeque<Notice>>` with a `take_if(|n| matches!(...))` under one lock, or per-kind slots.

**M14. "Refresh failed" is only ever reported on the Unread tab.**
`harbour-vuo.qml:64` polls `entries` first, so it always takes `Notice::SyncFailed`; `starredEntries.syncError` and `allEntries.syncError` are never set, yet `EntryListPage.qml:278-291` reads the *current* tab's error. Pull-to-refresh on All in airplane mode shows no banner; switching back to Unread later shows a stale one.
*Fix:* make `SyncFailed` a broadcast with a serial each model compares, as `updateSerial` does.

**M15. Every entry row clones the full base64 favicon, re-encoded on every reload.**
`models.rs:531` copies the whole `data:` URI into each `EntryRow`; `models.rs:527` calls `refresh_feed_chrome()` on every reload, re-reading and re-encoding every icon (up to 512 KiB each, about 700 KB as base64). Three models each reload on every generation bump, and every local tap bumps. A few feeds with 100-300 KB multi-resolution `.ico` favicons times 500 rows times 3 models is tens of MB resident, re-allocated per bump.
*Fix:* `Rc<str>` in `FeedChrome`/`EntryRow`, or look the URI up in `data()`; rebuild chrome only when feeds or icons change.

**M16. "Mark all as read" on All/Starred loads every article body to collect ids and enqueues rows for already-read entries.**
`models.rs:463-473` calls `store::list_entries(..., i64::MAX, 0)`, whose SELECT includes `content`; `apply_local_status_bulk` (`worker.rs:717-729`) then queues every id unconditionally. On a 20 000-entry mirror that is every body in memory, 20 000 outbox rows and 20 000 ids PUT on the next flush.
*Fix:* add `store::unread_entry_ids(filter)` in core; queue only entries whose status differs.

### QML (`qml/`)

**M17. Article images are only width-capped; a tall image decodes at full resolution.**
`qml/pages/ArticlePage.qml:367` sets `sourceSize.width: block.width` and no height. Qt only downscales when the source exceeds the requested dimension, so a 1000 x 30000 image (30 Mpx, about 120 MB decoded) served through the proxy, or with policy "Always load", is decoded whole. With `cacheBuffer: height*4` and `cache: true`, several can be alive at once. The comment claiming the cap prevents memory exhaustion is not true.
*Fix:* also set `sourceSize.height: block.width * 4`; consider dropping `cache: true`.

**M18. `imageRatio` up to 20 000 reserves a 21-million-pixel-tall blank block.**
`ArticlePage.qml:355-360` computes `height = width * imageRatio` whenever the image is not `Ready`, which includes permanently after `Image.Error`. Rust caps each dimension at 20 000 (`transform.rs:1062-1070`) but not the ratio, so `width="1" height="20000"` gives a ratio of 20 000. The comment in `article.rs:150-152` saying the caps prevent "a silly rectangle" is wrong. A proxied `<img>` that 404s produces a 1080 x 21 600 000 px empty item and the article becomes unscrollable.
*Fix:* clamp the ratio (about 3) in QML or Rust, and collapse the block on `Image.Error`.

**M19. Quadratic feed-name fitting on an unbounded foreign string.**
`qml/components/EntryListView.qml:396-403` (`fitName`) trims one character per iteration and measures the whole remaining string each time, for up to four rungs per row, re-run on every width change. No length cap exists on `feed_name` or `title` anywhere in core or the shim. A 20 000-character feed title freezes the list for seconds and again on rotation.
*Fix:* pre-truncate to about 80 characters before fitting, or binary-search the trim length.

## 4. Low

### Credentials and files

- **L1. The account file is not written atomically.** `worker.rs:937-963` opens with `truncate(true)` then `write_all`; no temp file, rename or `sync_all`. Power loss between truncate and write leaves a 0-byte `account.json`; `load_account` says "malformed", the app starts with no context and no explanation, and `AppPaths::configured()` still says configured, so `--sync-once` exits 1 with a warning on every timer tick. The permission handling itself (0600 before any byte is written) is correct.
- **L2. There is no way to remove the stored token.** `settings.rs:217-219` returns early when either field is blank, so clearing the fields leaves the previous plaintext `account.json` on disk. No `remove_file` exists in the shim.
- **L3. "Test connection" silently persists the credentials and restarts the worker.** `settings.rs:299` calls `save_to(paths)` from `test_connection_with`. Probing a wrong key overwrites a working stored key, and the worker is retired and respawned mid-sync. Build a throwaway `Transport` for the test instead.
- **L4. `Account` derives `Debug` with a plaintext `token: String`.** `worker.rs:857-861`. No `{:?}` of an `Account` exists today, but the core went to the trouble of a redacting `ApiToken` and the shim does not use it. Store `ApiToken` with a custom serde impl, or write a redacting `Debug`.
- **L5. The data directory is created with the default umask.** `worker.rs:932`. `vuo.sqlite` (article bodies, consent origins) is typically 0644 on a multi-user host. The token file is 0600.
- **L6. `Settings.apiKey` exposes the full token as a QML-readable property.** `settings.rs:72`, `:159`. Expected for an editable field, but it means any QML in the app can read it.
- **L7. Userinfo in the server URL is accepted** (`transport.rs:129-137`) and reqwest sends it as Basic auth. Redaction covers the logging side; consider rejecting it at setup.

### Process safety and behaviour

- **L8. `std::thread::spawn` can panic on the Qt thread.** `settings.rs:454`, reached from `Component.onDestruction`. With `panic = "abort"` this is an abort rather than UB, but it breaks the crate's own rule; `worker.rs:272` already shows the `thread::Builder::spawn(...).ok()` pattern.
- **L9. Every failed sync bumps the generation, scrolling every list to the top.** `worker.rs:363-364` sets `changed = true` unconditionally in the error arm. Bump only when something was committed.
- **L10. `FetchOriginal` reports success for an entry that no longer exists.** `worker.rs:483-492` maps "no row" to `""`; the `UPDATE` affects 0 rows but is `Ok`, so `FETCH_OK` is posted and the article view clears. Also `worker.rs:384-388` discards the post-subscribe sync error, including an auth failure.
- **L11. Qt-thread database writes can block up to 5 s behind a worker transaction.** `db/mod.rs:72` sets `busy_timeout(5 s)` on every connection, and local mutations run inline on the UI thread by design. Tapping "star" during a large upsert stalls the UI until the worker commits. Acceptable if documented; otherwise a short timeout on the UI connection with a soft failure.

### Transform correctness

- **L12. List indent and quote depth desynchronise from the open stack past their caps.** Open pushes only under the cap (lines 724-729, 749-755); close pops unconditionally (917-924). Text after partially closing deep nesting gets the wrong indent.
- **L13. `<script/>` and skip elements nested inside another skip leak their bodies as text.** Lines 640-642 and 609-621. `<script/>alert('x')</script>` renders `alert('x')` as article text. Escaped, so not injection, but it is the allowlist breach the module's own comments treat as one. Falls out of the M1 fix.
- **L14. Every `Skip` element flushes the current paragraph** (line 630). Inline `<svg>`, `<button>`, `<input>`, `<video>` inside a `<p>` split it into three paragraphs.
- **L15. `&nbsp;` and other Unicode spaces are collapsed as ordinary whitespace.** `collapse_whitespace` (1106-1122) uses `char::is_whitespace`; the doc says ASCII. `1&nbsp;&nbsp;000` becomes `1 000`. Browsers never collapse NBSP.
- **L16. Whitespace after `<br>` is not collapsed.** `push_text` (542-545) checks only for a trailing space. Pretty-printed HTML gives `"a\n b"`.
- **L17. Table caps mis-report and overflow cells append to the last cell.** Lines 804-812 skip cell creation, then `flush` (453-459) appends the text to the previous cell. A wide table is reported as `TooManyBlocks` although the block count is 1.
- **L18. `alt`, `title` and `language` are unbounded and unfiltered.** Lines 851-853 and 1091-1104. A 5000-byte `alt` passes a 10-byte text cap with `truncated: None`; `class="language-<b>x"` yields `language: Some("<b>x")` up to 2 MB. Charge them to the budget and allowlist `language` to `[a-z0-9+#.-]{1,32}`.
- **L19. `<img>` and `<hr>` inside `<pre>` are emitted before the code block** (835-860 does not check `pre_depth`).
- **L20. The fuzz target does not assert the caps that fail.** `fuzz_targets/content_transform.rs:53-65` checks blocks, depth, indent and scheme but not text bytes, span count, or table caps, and only renders paragraph/heading/list spans through `assert_no_foreign_tags`, never table cells. M1 and M2 are invisible to it. A cheap strong invariant: `serde_json::to_vec(&document).len() <= K * input.len() + C`.

### Database and sync

- **L21. `icon_failures` is never reset when the server assigns a new `icon_id`.** `store.rs:117-134`. A feed whose old icon failed three times never fetches its replacement.
- **L22. `taxonomy` derives the "live" feed set from *converted* feeds** (`pull.rs:92-95`). `convert::feed` is infallible today; the first validation added there turns a rejected feed into an unsubscribe cascade that deletes entries and outbox rows. Compute `live` from raw wire ids.
- **L23. Keyset pagination stalls on non-positive ids.** `client.rs:175-177` sends `after_entry_id` unconditionally; Miniflux ignores it when `<= 0`. `model.rs:16-21` claims the cursor survives such ids; verify against the server and document the limitation if confirmed.
- **L24. The reconcile's count-equality guard is a heuristic.** `pull.rs:370`. A skipped id compensated by a new id later in `id DESC` order deletes a live entry. Contrived, but cheap to harden by confirming each stale candidate with `GET /v1/entries/{id}` when the candidate count is small.
- **L25. Orphan entries with no `feeds` row are never removed** (`pull.rs:128-132`). One `DELETE FROM entries WHERE feed_id NOT IN (SELECT id FROM feeds)` after the feed upsert fixes it.
- **L26. Enclosures are keyed by the server's enclosure id alone** (`store.rs:277`, `INSERT OR REPLACE`). Colliding or defaulted ids silently move enclosures between entries. Key on `(entry_id, id)`.
- **L27. Write-only columns and fields.** `last_seen_sync` on three tables, `outbox.attempts` and `last_error` (so there is no backoff: a persistently-5xx batch is resent every pass), `sync_state.server_era`, `PendingMutation.attempts`. Use them or drop them.
- **L28. Latent migration hazard: foreign keys are ON during `migrate`.** `db/mod.rs:85` sets the pragma before `migrations.rs:217` opens the transaction, where it cannot be changed. A future rename-copy-drop on a parent table fires `ON DELETE` actions mid-migration. Set FK off for the migration connection and run `PRAGMA foreign_key_check` after.

### Build, CI and supply chain

- **L29. `make msrv` is broken by construction.** `Makefile:16` says `MSRV ?= 1.75.0` while `Cargo.toml:44` says `rust-version = "1.88"`, and the README advertises `make msrv` as the floor check. Running it installs 1.75 and fails on edition2024 dependencies. The CI job reads the value from `Cargo.toml`, so the two disagree. Read the Makefile value from `Cargo.toml` too.
- **Actions are pinned by tag or branch, not by commit SHA.** `dtolnay/rust-toolchain@master`, `@stable`, `@nightly`, `taiki-e/install-action@v2`, `Swatinem/rust-cache@v2`, `actions/*@v4`. A mutable ref is the standard supply-chain gap; SHA-pin and let Dependabot bump. The container images in the integration workflow are already documented as tag-pinned.
- **`rust-toolchain.toml` pins `channel = "stable"`,** and its comment says this makes rustfmt and clippy "behave identically everywhere". A moving channel does not do that; a clippy release can turn `-D warnings` red on a fresh runner. Pin a version (`1.94.1`) and bump deliberately.
- **Bundled SQLite is 3.46.0** (`libsqlite3-sys 0.30.1` via `rusqlite 0.32`). Two advisories are published against that version: CVE-2025-29087 (`concat_ws` integer overflow, 3.44.0-3.49.0) and CVE-2025-6965 (aggregate-term overflow, before 3.50.2). Both need attacker-controlled SQL, which Vuo never executes, so exposure is nil in practice. `rustsec` does not carry them, which is why `cargo audit` is clean. Bump `rusqlite` when the SDK floor allows.
- **README claims `make check` runs exactly what CI runs,** but CI also runs the `msrv` and `fuzz-smoke` jobs, which `make check` does not. Minor, but the claim is load-bearing in the docs.
- **`tests/fixtures/seed.opml` points the integration job at real third-party feeds.** Import failures are tolerated (`|| true`), but the job's outcome still depends on external hosts, and each run fetches from them.

## 6. What is done well

This section is short because the material is in the findings, but it matters for prioritisation: none of the hardening below needs to be redone.

- **Transport.** The token is a redacting newtype whose only accessor is named `expose`. Redirects are resolved by hand with `Policy::none`, an exact scheme-host-port origin check, a plaintext-downgrade refusal and a shrinking whole-call deadline. The extra CA is additive and cannot degrade verification. `reqwest::Error` is never chained, so its URL-carrying `Display` cannot leak userinfo. Bodies are declared-length checked and then streamed against a cap. A test scans the whole crate for `danger_accept_*`, `tls_built_in_root_certs`, `use_preconfigured_tls` and `cookie_store`. Cookies are absent by feature, not by configuration. Everything tried against the origin and media checks (protocol-relative, userinfo tricks, homograph hosts, trailing dots, port normalisation, entity-encoded schemes, tab-split `java\tscript:`) was handled correctly.
- **Storage.** Every statement is parameterised; `pragma_update` is used only with literals and a self-owned integer; a structural test enforces it. `with_tx` uses `BEGIN IMMEDIATE` with a two-connection regression test. Migrations re-read `user_version` inside the transaction, refuse newer schemas, and are checked against frozen on-disk fixtures with a schema-equality assertion, which catches a shipped migration being edited in place. No transaction is held across an `await` anywhere.
- **Outbox.** A keyed desired-state map rather than an operation log, compare-and-delete confirm, explicit avoidance of the server's toggle endpoints (whose SQL is `SET starred = NOT starred`), and local expansion of mark-all-read to avoid the server's request-time cut-off. This is the right design and it is well argued in `docs/api-contract.md`.
- **Content.** Tokenizer-only with a flat output and scalar depths, which eliminates the recursive-drop class outright. The allowlist is the `BlockKind` enum; there is no passthrough. `MediaUrl` enforces http(s) in every constructor including `Deserialize`. All markup emission funnels through one escaped, fixed-tag renderer. The media decision is made in Rust before a URL can reach a QML `Image`, by parsed origin rather than path substring. Input is cut on a char boundary before parsing. No reachable panic was found.
- **Icons.** Sniffed by magic bytes, dimension-capped from the header before any decoder allocates, SVG refused outright, base64 length-checked before decoding, and bounded again with `sourceSize` in QML.
- **QML.** The `Text.PlainText` discipline is applied everywhere foreign text is shown, including the two places Silica's own widgets would have forced `AutoText`, where the title was moved into an explicit label with a documented reason. No `Qt.createQmlObject`, `Loader { source }`, `eval`, `console.log`, `Clipboard` or `Notification` use. The API key only ever lands in a `TextInput.Password` field. The cover explicitly refuses to render the error text it receives.
- **Threading.** No Qt object is touched off the Qt thread; no Qt pointer is captured in a callback; the worker publishes an atomic generation counter and a mutex-protected notice slot; `RefCell` and `Mutex` failures degrade rather than panic.
- **Verification culture.** The test suite documents *why* each cap exists by naming the bug that motivated it, and is honest about what each test cannot see. `docs/status.md` records nineteen bugs the project's own tooling found, including a negative `total` that would have wiped the mirror. The pub-fn-orphan guard, the fuzz seeding script and the frozen schema fixtures are each there because a real defect slipped past the previous check.
